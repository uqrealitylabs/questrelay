The v0.8.0 tag stopped before publishing its builds. A path-filter test read the tag environment while checking an explicit file list, then failed because every job appeared to be selected. v0.8.1 fixes that boundary and runs the full web, Rust, Quest and deployment checks before publishing anything

### Pick the build you need

| Download | Use it for |
| --- | --- |
| `questrelay-quest-debug-v0.8.1.apk` | ADB testing on a Quest with Developer Mode. This is debug-signed and cannot stand in for a Meta release-channel build |
| `questrelay-linux-x86_64-v0.8.1` | Running the Rust relay on a compatible Linux x86_64 host after setting the required keys and media address |
| `questrelay-server-v0.8.1.tar.gz` | Building the web and relay from the tagged source on a Docker host with the included Compose configuration |
| `.sha256` files | Checking the downloads before installing them |

The same workflow publishes `ghcr.io/uqrealitylabs/questrelay-backend:v0.8.1` and `ghcr.io/uqrealitylabs/questrelay-frontend:v0.8.1`. The repository is private, so pulling those images requires package access. The [deployment guide](https://github.com/uqrealitylabs/questrelay/blob/v0.8.1/docs/DEPLOY.md) covers HTTPS, keys, the media port and backups

This release still uses the self-hosted relay. Cloudflare Realtime is being integrated separately. One Quest has sent video and an Opus track to a local browser. Audible game audio, several headsets at once and internet latency still need measured tests
