QuestRelay can now run its public room and control room on Cloudflare without a VM. A Quest companion app sends H.264 video and Opus device audio over WebRTC to Cloudflare Realtime SFU, and browsers subscribe directly to the feeds they watch. The self-hosted Rust relay remains available for local and Docker installs

## What changed

- A Rust Worker handles room access, short per-headset links, publisher and viewer sessions, admin sign-in and control signals, with D1 storing room settings and recent diagnostics
- The Quest app has 720p and 1080p capture choices, 30 and 60 fps targets, and Auto bitrate control informed by RTCP uplink loss. Settings stay on each headset, with the publisher key encrypted by Android Keystore
- The public viewer separates recent packet loss from the total lost in its current session. The control room shows the Quest's actual encoded frame rate and uplink loss, and marks the Cloudflare send queue as **Not measured**
- `tools/scripts/deploy.sh` now has `cloudflare`, `server`, `adb devices` and `adb send <id>` commands. The device command builds and installs the APK on the selected Quest only

## What we measured

In a live Quest 3 and Safari test with Beat Saber, H.264 video and an Opus track reached the browser. The game renderer reported 90 fps, while the QuestRelay encoder produced about 29–30 fps at both 1080p and 720p with a 60 fps target. On one 720p receiver sample, recent video loss was 0%, the session had 11 earlier lost packets and network RTT was 13 ms. A second Quest 3 connected as a separate feed after installation. These are observations from this test, not throughput or latency guarantees

The 720p profile reduced the data rate compared with 1080p. It did not raise the actual capture frame rate. We have not measured glass-to-glass delay or verified simultaneous multi-headset capacity, audible game audio, stable 60 fps or a normal Meta release-channel install. Cloudflare admin access still uses a key, while the self-hosted backend has passkey support

## Downloads and deployment

The release downloads include a Quest debug APK for ADB testing, a Linux x86_64 relay binary, a self-hosted server bundle and SHA-256 checksums. The Docker images are published separately at:

```text
ghcr.io/uqrealitylabs/questrelay-backend:v0.9.0
ghcr.io/uqrealitylabs/questrelay-frontend:v0.9.0
```

The [Cloudflare guide](https://github.com/uqrealitylabs/questrelay/blob/v0.9.0/docs/CLOUDFLARE.md) covers Worker secrets, D1 and Quest setup. The [single-host guide](https://github.com/uqrealitylabs/questrelay/blob/v0.9.0/docs/DEPLOY.md) covers the Docker path
